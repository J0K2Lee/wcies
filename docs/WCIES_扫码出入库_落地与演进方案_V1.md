### 系统能力(已实现,勿重做)

- 四个扫码作业页:收货(扫码加行+当场绑条码)、拣货(单件原子+SN+防超扫)、装箱(扫码+封箱+SN 进度)、拦截(SKU+SN+**库位**三扫→回库)
- 库位引导:拣货页显示"下一库位",按 `bin_code` 字典序=行走顺序;扣哪个库位由**分配时的每库位分配行**决定,与扫码位置无关
- SN 全链:收货写入→拣货/装箱校验→出库→拦截回库
- 条码体系:`sku_barcodes` 多类型+全局唯一+`/barcodes/{barcode}/resolve`+未知条码现场绑定;内部码 `W%08d`
- 打印:Code128 的 SKU_LABEL / BIN_LABEL / SHIPPING_LABEL 三种
- 发货门禁:未装满/未封箱不能 ship;幂等键防重

### 已排除的选项(勿再议)

## 1. 第一阶段:零开发,今天可执行

按顺序,全部是使用/配置动作:

1. **打印标签**
   - SKU 条码:SKU 页(`SkusPage`)打印
   - 库位标签:库位页(`BinsPage`)打印 —— **必打**:拦截流程的库位扫码是必填项
2. **枪的开箱三步**
   - USB 插入即用(HID,免驱动)
   - 记事本冒烟:扫一次出一条**并换行** = 回车后缀正确;否则扫说明书里的"CR 后缀"设置码
   - 输入法切英文态(Win+空格)——中文 IME 会吞字母
3. **十分钟验证链路**(真实单据)
   - 收货页扫码加行(未知条码当场绑定)→ confirm 入账
   - 订单重试分配 → 创建拣货单 → 拣货作业页:照"下一库位"拿货,扫 SKU(SN 商品再扫 SN)
   - 创建发货单 → 建包裹 → 装箱扫码 → 封箱 → 打印面单 → ship 出库
4. **手机接入(可选,移动查看/作业)**
   - 手机同 Wi-Fi 开 `http://192.168.1.12:5173`,登录同一账号
   - 打不开 → 放行 Windows 防火墙 5173 入站
   - 要看商品图 → `.env` 的 `S3_ENDPOINT` 改 `http://192.168.1.12:9000` 后重启栈(纯扫码流程不受影响)
   - 已知限制:界面按桌面布局设计,能用不完美
5. **(可选采购)蓝牙扫码枪**:配对手机=移动扫码,零开发;USB 枪留工位

**阶段验收**:一单真实闭环走完,`external_raw_events`/订单/库存流水/`package_item_serials` 账实一致;作业过程中无"扫码丢失"导致的重复扫或漏扫记录。

## 2. 第二阶段:小改造包(边界清晰,按真实痛点挑用,不预做)

> 启用规则:第一阶段真实跑 1–2 周后,按观察到的痛点选包。每包独立,互不依赖,均可作 Sprint 10 候选。

| 包 | 内容 | 改动面 | 前置业务决策 |
|---|---|---|---|
| **A 扫码体验** | 全局 keydown 扫码捕获(枪特征:击键间隔<10ms+回车终止;根治焦点丢失)、成功/失败 beep(Web Audio)、四页扫码输入收敛为共享 `ScanInput` 组件 | 纯前端 | 无 |
| **B 收货逐件计数** | 扫一次计一件(现状态是"扫码加行、数量手填"),同 SKU 连扫自动累计;到货数与单据数差异高亮 | 纯前端 | 无 |
| **C 拣货扫库位强校验** | 拣货页加库位输入框;后端把 `binBarcode` 的「存在性校验」升级为「== 本行分配库位」并让扣减跟随实扫库位行(现状:传了也只查存在,`picking.service.ts:262`) | 前端+后端各一小块 | **扫库位是强制还是可选**(强制增加作业步骤,可选只做提示) |
| **D SN 查询入口** | 按序列号查状态/库位/所属预约(只读端点+页);串号排查、售后溯源 | 后端只读端点+前端页 | 无 |

**启用建议**:A 里「全局捕获+beep」最可能被真实痛点触发(焦点丢失与漏看失败是现成风险);C 等"同一 SKU 多库位+拿错格子"实际发生再做;B 在到货量大时才有感;D 遇到第一次串号排查再做。

## 3. 第三阶段:规则未定,不排期(定了规则才立 Sprint)

**库位级盘点** —— 扫码出入库最大的闭环缺口(账实漂移目前唯一系统性纠正手段)。
实施前必须由用户定义:

1. 盘点粒度:按库位盘 / 按 SKU 盘 / 按 SN 逐件盘(SN 商品强制逐件?)
2. 差异入账:走现有手工调整(`AdjustStockRequestDto` + reason)还是新业务动作?是否需要审批/异常(如 `STOCK_DIFFERENCE`)
3. 盘点期间:被盘库位是否冻结新分配?在途 Reserved/Picked 怎么处理?
4. 盘点单形态:全盘 / 循环盘 / 按库区抽盘;盲盘(不显示账面数)与否

以上属业务规则,按 AGENTS.md §2 由用户定义,不得由 AI 自行设定。

## 5. 红线与风险

1. **webhook 订阅已生效 ⇒ 隧道常开**;要长期关机/关隧道,先在 OZON 后台删地址,否则通知被平台自动暂停,恢复需人工重新确认 URL(ozon.md §6.5)。
2. 开发库含真实业务数据,不可重建;第二阶段涉及真实单据的改造,按 §89 谨慎操作。
3. 现有拣货"库位用看的"模式:**SKU 级账永远自洽,库位级准确性依赖照屏行走**。在 C 包或盘点落地前,避免依赖库位级账做精细管理(如指定库位补货)。
