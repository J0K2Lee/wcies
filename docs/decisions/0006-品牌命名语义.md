# 0006 品牌命名语义

- **状态**：已接受（2026-09-11，Sprint 6 手工测试修复）
- **决策人**：用户（任务书第 3 节决策 #11）

## 背景

原品牌表只有 `name_zh`（必填）/ `name_en` / `name_ru` 三字段。跨境业务中品牌主显示名不一定是中文（如 "Anker"、"Apple"），强制把品牌原名填进 `name_zh` 语义错位（用户手工测试问题：商品 2）。

## 决策

品牌命名采用**四个语义槽**：

| 字段 | 语义 | 必填 | 用途 |
|---|---|---|---|
| `name` | 一般名称（General Name） | 是 | **主显示名**，全站默认显示 |
| `name_zh` | 中文名 | 否 | 中文语境补充 |
| `name_en` | 英文名 | 否 | 英文语境补充 |
| `name_ru` | 俄文名 | 否 | 俄文语境补充 |

迁移：原 `name_zh` 列改名为 `name`（一般名称），再新增可空的 `name_zh` 列并回填 `name_zh = name`（原值语义上就是中文名，初始相同合理）。

## 理由

1. **主显示名必须独立于语种**：品牌方对显示名有唯一正确答案（通常是其注册名），不应该由系统替用户决定用哪个语种显示。
2. **其余语种是补充而非平级**：列表、详情、下拉默认显示 `name`；多语种只在需要时（如生成平台刊登文案）取用。
3. **回填语义**：存量数据的 `name_zh` 值即为当时的品牌名，同时作为一般名称与中文名保留，不丢信息。

## 影响

- 后端 Entity / DTO / Response 同步改名（`nameZh` → `name`，新增可空 `nameZh`）。
- 前端品牌表单字段改为：一般名称（必填）/ 中文名 / 英文名 / 俄文名；全站默认显示一般名称（替换所有 `nameZh` 引用）。
- 商品 / SKU 表仍保持 `name_zh` / `name_ru`（本决策只改品牌）。
