# 0009 履约模式的两层模型：存储用平台值，展示用业务类别

- **状态**：已接受（2026-09-11，二次手工测试修复）
- **决策人**：用户（"方案 C：两层模型"）

## 背景

用户提出店仓绑定的履约模式应显示为"自管仓 / 半托管 / 托管仓"，因为现有界面对 OZON 店铺列出 `OZON_RFBS / OZON_FBS / OZON_FBO / OZON_FBP`、对 WB 店铺列出 `WB_FBS / WB_FBW`，共 8 个平台专属值，标签还是"真仓配送 / 真仓入库 / 平台仓"这类难懂的措辞。

评估过三个方案：

- **A 只改显示文案**：改动最小，但下拉框仍是 4 个选项、看不出类别归属。
- **B 改成 3 个通用枚举值**：语义最简洁，但需要 Migration 迁移现有绑定、重写校验与 `master-data.md §7`，且会**静默破坏一条冻结规则**。
- **C 两层模型**：存储保留平台值，新增派生的展示类别。

## 决策

采用方案 C。

1. **存储层不变**：`store_warehouse_bindings.fulfillment_mode` 继续存平台专属值（8 个），无 Migration。
2. **新增派生类别层**（不落库，`fulfillmentCategoryOf()` 纯函数派生）：
   - `SELF_MANAGED` 自管仓 ← `OZON_RFBS`、`OZON_FBS`、`WB_FBS`、`YANDEX_FBS`
   - `SEMI_MANAGED` 半托管 ← `OZON_FBP`
   - `MANAGED` 托管仓 ← `OZON_FBO`、`WB_FBW`、`YANDEX_FBY`
3. **下拉框按业务类别分组**，且**只列出当前店铺平台适用的模式**（新增 `fulfillmentModesForPlatform()`）。
4. 列表列显示"自管仓 FBS"（类别 + 平台码），悬停显示完整说明。
5. 新增平台的流程为：常量表加值 + 类别映射加一行，前端自动生效。

## 理由

1. **方案 B 会静默破坏冻结规则**。`orders.md:75` 规定仓库选择"同优先级时非 FBO 模式优先（FBO 平台仓库存由平台管理）"，实现是 `order-ingestion.service.ts:358` 的 `fulfillmentMode.includes('FBO')`。若存储值变为 `MANAGED`，`'MANAGED'.includes('FBO')` 恒为 `false`，这条规则**不会报错、只会失效**——而 AGENTS.md §97 明确禁止为了实现方便而简化业务规则。
2. **订单还携带自己的履约模式**。`orders.fulfillment_mode` 是平台上报的事实（`ozon.mapper.ts` 写入 `FBS`），与绑定配置值是两回事。存储值改成通用枚举后，订单的 `FBS` 与绑定的 `SELF_MANAGED` 再也对不上号，排查"这单该从哪个仓发"时断链。
3. **与平台后台对得上**。卖家在 OZON 后台看到的就叫 FBS/FBO/FBP；界面上若只有"托管仓"，沟通与排障时双方说的不是同一个词。
4. **信息不丢失**。方案 B 并没有消除平台差异，只是把差异从绑定搬进 Adapter——未来实现 RFBS（自行发货给买家）与 FBS（发货至平台分拣中心）的不同流程时，仍需重新区分二者，而那时绑定已经不存这个信息了。
5. **类别是派生值**。与本项目"派生值不落库"的一贯原则一致（同 Available 不得成为第二事实源，AGENTS.md §13）：类别由模式派生，不可能与模式漂移。

## 影响

- `platform.constants.ts` 新增 `FULFILLMENT_CATEGORIES`、`fulfillmentCategoryOf()`、`fulfillmentModesForPlatform()`。
- `StatusBadge.tsx` 的 `FULFILLMENT_MODE_META` 统一承载 platform / category / label / hint 四要素，替换原 `FULFILLMENT_MODE_LABEL`（保留为兼容导出）。
- 修复既有缺陷：绑定表单原先对**任何**店铺都列出全部 8 个模式，给 OZON 店铺选 `WB_FBS` 必被后端拒绝；现在按平台过滤。
- 新增单元测试：类别分类完整性、平台隔离（OZON 不出现 WB/YANDEX 模式）、FBO 与 FBS 类别必须不同（守住 `orders.md §4.6`）。
- `master-data.md §7` 的履约模式集合不变，仅补充"另有一层用于展示的业务类别"说明。
