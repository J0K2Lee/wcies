# ADR 0023 — 采购单目标仓与 SKU 级缺口

日期：2026-10-21（用户拍板，采购语义重构）
状态：已接受

## 背景

用户提出两个现象：

1. 存在「采购后已收货、订单行却仍显示缺货」的订单；
2. 「已采购」标记在缺货消失后仍然残留（显示为「已到货」）。

根因是旧模型把采购**挂在订单行**上（`purchase_order_items.order_item_id`）：

- 订单行 `A` 买了货，收货入库后是**该仓库的整体库存**增加，不保证被 `A` 占用；
  如果同一 SKU 还有更早的订单行 `B` 缺货，自动分配会把新库存给 `B`——
  `A` 依然缺货，而 `A` 的采购明细已经「收完」，于是显示「已到货 + 缺货」。
- 这个组合态在业务上无法解释：已到货的货去哪了？答案是被别的订单拿走了。
  用户明确：**这种「已到货」不应该存在**。

用户给出的判断：

> 一个采购单，肯定有明确的地址送货，即目标仓库。把选仓库交给采购单处理。

> 既然无归属（不再挂订单行），那么还记录哪个订单触发的，有意义吗？

## 决策

### D1. 采购单必须有目标仓

`purchase_orders.receiving_warehouse_id` 由「可空意向」升级为 **NOT NULL**：

- 创建必填，校验仓库存在（`WAREHOUSE_NOT_FOUND`）；
- 已有未取消收货记录后不可更改（库存事实已落在原仓）；
- 收货单仓库强制等于目标仓，请求传别的仓 → `PURCHASE_RECEIPT_WAREHOUSE_MISMATCH`。

历史数据迁移 `20261021_004_purchase_order_target_warehouse.ts`：先按该 PO 名下
最老收货单的仓库回填，退回店铺默认绑定仓；仍有 NULL 则由 `DO` 块抛错中止
（不静默猜测，AGENTS §89）。本次执行结果：96/96 全部回填。

### D2. 采购不再挂订单行

`purchase_order_items.order_item_id`：

- **不再写入**（新建/替换明细一律 NULL）；
- **不再参与任何判定**（旧的「同一订单行重复登记」守卫删除）；
- **列保留**：历史数据仍可查、可回显（AGENTS §99 不删列）。

误报的错误码随之下线：`PURCHASE_ORDER_ITEM_ALREADY_ORDERED`、
`PURCHASE_RECEIPT_WAREHOUSE_MISSING`、`PURCHASE_ORDER_LINE_NOT_ORDERED`。
「订单行去收货」入口（`POST /purchase-receipts/from-order-item/:orderItemId`）删除。

### D3. 缺口按 SKU × 仓计算，在途按分配优先级覆盖到行

```text
需求(SKU, 仓) = 该仓服务店铺下该 SKU 的未分配行数量之和
在途(SKU, 仓) = 该 SKU + 目标仓 所有未取消采购单的 max(quantity − received, 0)
缺口          = max(0, 需求 − 在途)
```

覆盖不是「谁买的归谁」，而是把在途数量**按库存分配的同一优先级**逐行切分
（ADR 0022：加急 > 平台 > 时限 > 先后），累计量 ≤ 在途即该行 `COVERED`。

行归属仓与订单分配同规则：店铺 `ACTIVE` 绑定中 `priority` 最小、非 FBO 优先。

### D4. 补货采购做缺口守卫，备货采购不做

`POST /purchase-orders` 新增 `purpose`：

| purpose | 来源 | 缺口校验 |
|---|---|---|
| `REPLENISH` | 订单页「创建采购单」 | 有：`缺口 = 0` → `PURCHASE_SKU_GAP_COVERED`；`数量 > 缺口` → `PURCHASE_ORDER_INVALID_STATE` |
| `STOCK`（默认） | 采购单页备货 | 无：同 SKU 可多张并存 |

守卫在创建事务内执行，并对 `(skuId, warehouseId)` 加 `pg_advisory_xact_lock`，
锁内重算缺口——两人同时为同一缺口各买一份会被串行化挡住。

### D5. 「已到货」整体移除

派生状态从 `{NOT_ORDERED, ORDERED, ARRIVED}` 改为 `{COVERED, SHORT}`：

- `COVERED`（已采购）：缺口已被在途覆盖；
- `SHORT`（仍缺）：显示缺口数量 + 「登记采购」入口。

货到仓后库存增加事件触发自动分配，缺货行当场变成已占用，不存在「到了货还缺」
的中间态；因此列表级的「已到货 N / 重新分配 N」入口一并删除，只保留单行
`retry-allocation`。

## 明确不做

- 不做「采购单锁定到具体订单行」的任何形式（含软锁定）——用户判断没有业务价值。
- 不做跨仓调拨补缺口：缺口只在目标仓内闭环，跨仓是 Transfer 模块的事。
- 不按订单预占在途库存：覆盖是只读派生，不落库、不产生 Reservation。

## 影响

- `purchase_order_items` 新行 `order_item_id` 恒 NULL（旧行保留原值）；
- 订单列表 DTO：`backorderedOrderedCount/backorderedArrivedCount` →
  `backorderedCoveredCount/backorderedShortCount`；行级 `procurementState` →
  `procurementCoverage/procurementGapQty/procurementInTransitQty/procurementWarehouseId`；
- 采购单创建/批量生成收货单不再询问仓库；订单页右栏只剩「创建采购单」；
- 采购模块不再 import 订单模块，`ORDER_PROCUREMENT_PORT` 单向下行（去掉 forwardRef）。

## 验证

实施当日对开发库执行覆盖 SQL：29 条缺货需求行 → 26 条 `COVERED`（对应 26 张
ORDERED 采购单共 26 件在途）、3 条 `SHORT`（该 SKU×仓在途为 0），与人工核对一致。
