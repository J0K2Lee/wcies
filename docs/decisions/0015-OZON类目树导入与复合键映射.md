# ADR 0015 — 类目体系：OZON 树导入、缓存表与复合键映射

日期：2026-09-14（Sprint 8.5，grilling 会话决策定稿）
状态：已接受

## 背景

- 内部分类三级模型（决策 0005）与 OZON 类目之间没有映射通道；建档弹窗无类目字段。
- 人工在俄语类目名下做映射成本高；T0 冒烟（2026-09-14，`docs/integrations/ozon.md` §8）证实
  `/v1/description-category/tree` 的 `language=ZH_HANS` **官方直出简体中文**，质量可用。
- 冒烟同时确认两个关键结构事实：真实树**恰好三层**（26 根 / 542 二级 / 7365 个 type），
  type 节点**不携带** `description_category_id`；19 个 type_id 挂在多个父类目下。

## 决策

1. **树缓存**：`platform_category_nodes`（integration/ozon 域）存双语节点（`name_zh`/`name_ru`、
   `node_kind ∈ {CATEGORY, TYPE}`、`level` 1..3、`disabled`）；手动触发同步
   （ZH_HANS + RU 各拉一次按键合并），按 SyncJob 记录，不做定时再同步。
   唯一键 `(platform_id, external_category_id, COALESCE(external_type_id, -1))`。
2. **复合键**：`platform_category_mappings` 以 `(platform_id, external_category_id,
   external_type_id)` 唯一映射内部三级分类；TYPE 行的 category 部分取**父类目** id。
   仅按 type_id 映射会产生歧义（19 个多父 type），被明确否决。
3. **导入粒度全保真**：OZON type 逐个建为内部三级类目（接受千级节点量级，Cascader 配搜索）；
   层级塌缩规则为 1:1 直映（真实树三层）；仅导入 `disabled=false`。
4. **导入流程**：dry-run 预演（不落库：节点统计 + 建树预览 + 与现有分类按 `name_ru`
   精确查重的冲突清单）→ 确认后**单事务**批量执行（categories 经 catalog 公开 Service
   批量建、`CN%05d` 批量取号、映射行 source=TREE_IMPORT）。存在冲突时执行 409 拒绝
   （AGENTS §89：禁止静默丢弃）。
5. **弹窗填充**：从 `raw_data` 读 `(description_category_id, type_id)` 复合键精确匹配；
   命中自动选中（可改），未命中人工三级 Cascader；「记住此映射」（默认勾）在 onboard
   同一事务写映射行（source=ONBOARD，`ON CONFLICT DO NOTHING`）。
   **永不按名称相似度自动匹配。**
6. **模块归属**：树缓存表与同步器在 `integration/ozon`；`platform_category_mappings` 与
   导入编排在 `listing` 模块（与 `platform_listing_skus` 同域）；建类目经 catalog 公开
   Service，禁止循环 HTTP、禁止跨模块 import Repository。

## 后果

- 真实树存在同父级下同名 type（2026-09-14 全树 57 组），与内部同父名称唯一索引冲突：
  导入对第二及以后的同名候选**确定性追加外部 id 后缀**并在预演报告列出（§89 不丢弃）。
- 两张新表 + 1 个 Migration；`sync_jobs.sync_type` CHECK 扩展
  `CATEGORY_TREE_SYNC` / `PRODUCT_ENRICHMENT_SYNC`。
- 类目映射管理页后移：弹窗「记住」+ 一键导入已覆盖本期需求。
- `ZH_HANS` 中文质量若未来退化：降级为「纯人工 Cascader + 记住此映射」，翻译管线另行立项。
