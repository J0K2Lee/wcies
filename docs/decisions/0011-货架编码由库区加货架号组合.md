# 0011 货架编码 = 库区 + 货架号，两条创建路径共用同一规则

- **状态**：已接受（2026-09-11，用户指出单建弹窗歧义后修复）
- **决策人**：用户（"与批量统一：货架号只填数字"）

## 背景

决策 0010 统一了库位编码与条码，但**单建弹窗与批量弹窗对「库区」的解释不同**：

| | 库区的作用 | 填「库区 A + 货架 C01」的结果 |
|---|---|---|
| 批量建位 | 货架编码的**前缀**（区 A + 起始 1 → 货架 A01） | — |
| 新建库位（单建） | 仅作为 `zone` 标签，不进编码 | 编码 `ZG-01-C01-1`，`zone=A` |

用户在人工测试中发现该歧义：单建弹窗填写「库区 A、货架 C01、层 1、位 02」时，无法判断会创建立什么。实测确认系统照单全收，产出**「按库区筛选归到 A 区、但编码写着 C01」**的库位——标签与归属不一致。且单建弹窗当时没有预览，填的时候无法预知结果。

后果的严重性来自两个既有约束：`bin_code` 写入后不可修改（`UpdateBinRequestDto` 不含该字段），且库位有库存流水后不可删除。填错只能停用后另建，货架标签需重印。

## 决策

**单建的输入结构改为与批量一致：库区 + 货架号（数字），货架编码由服务端组合。**

- 新增 `formatRack(zone, rackNumber)`：区 `A` + 号 `3` → `A03`（补零到至少两位）。
- 单建与批量**调用同一个 `formatRack`**，两条路径在代码层面不可能再分叉。
- 单建弹窗的「货架」输入框改为数字型的「货架号」，并新增实时预览（与批量弹窗一致）。
- 层与位的**纯数字段去掉前导零**（`normalizeSegment`）：否则 `01` 和 `1` 会生成两个不同编码却指向同一个物理位置。
- 输入不足以生成编码时返回 422 `WAREHOUSE_BIN_BATCH_INVALID`，明确报错而非静默产出空段编码。

## 例外：Excel 导入

导入提供**完整 `bin_code`**，由调用方决定字符串。此时服务端按原样存入 `bin_code` 与描述列，**不做规范化**——否则描述列会被改写成与文件给定编码不一致的值，反而制造矛盾。因此规范化只作用于「服务端生成编码」这条路径。

## 影响

- `CreateBinRequestDto.rackNumber`（数字，单建用）与 `rack`（字符串，导入用）并存；`rackNumber` 优先。
- 库区仍是库位上的标签，不建独立实体（用户已确认方案 A）；它通过 `formatRack` 影响编码，因此「库区」不再是纯装饰字段。
- 已存在的历史库位（如 `TEST-A01`、`DEFAULT`）不回溯改写。
