# 0004 前端认证守卫与 401 处理策略

- **状态**：已接受（2026-09-11，Sprint 6 手工测试修复）
- **决策人**：用户（任务书第 3 节决策 #19；T5 规格）

## 背景

后端已通过全局 `APP_GUARD`（JwtAuthGuard，HttpOnly cookie `wcies_session`）防住所有非公开路由，但前端是 fail-open：`App.tsx` 裸 `<Routes>`，无认证检查。未登录用户访问任意页面会看到完整界面外壳 + 空数据列表（401 被渲染成"空列表"），造成"能进页面但没有数据"的误导（用户手工测试问题：用户管理 1）。此外：顶栏用户名写死 "Admin"，全站无退出登录，登录页无回跳。

## 决策

1. 新增 `AuthGate` 组件包裹受保护路由：启动时探测 `GET /api/v1/auth/me`（`retry: false`）→ 加载中显示加载态 → 未认证跳 `/login?redirect=<当前路径>` → 已认证渲染 children 并向顶栏提供真实用户信息。
2. 登录成功后读取 `redirect` 参数回跳原路径（无参数回 `/`）。
3. React Query 全局 401 处理：401 不重试（重试只会再拿一个 401）；会话过期时清认证状态、提示"登录已过期，请重新登录"、跳登录页；`/auth/login` 自身的 401（密码错误）排除在外，否则会把用户踢出登录页。
4. API 错误对象保留 `error.code` 与 `error.details`（自定义 `ApiError extends Error`），页面能显示可诊断的信息。
5. 顶栏显示真实用户名 + 角色，新增退出登录（调 `POST /api/v1/auth/logout` 后跳 `/login`）。
6. `/health-test` 内部诊断页保持在守卫内。
7. 本轮不做用户 CRUD（需先定权限模型）。

## 理由

1. **后端已守卫，前端为何还要 AuthGate**：后端守卫保证数据安全，但"外壳渲染 + 空数据"的 UI 是误导性的——用户以为系统坏了。AuthGate 把"未登录"显式化为登录页，而不是伪装成空系统。
2. **redirect 回跳**：用户因会话过期被打断时，登录后应回到原岗位，而不是每次都落到首页。
3. **401 不重试**：401 是确定性失败，重试无意义且拖慢反馈。
4. **保留 code/details**：`hooks.ts` 原来只取 `error.error.message` 丢掉 code，前端无法区分"未登录"和"业务错误"，也无法显示后端精心设计的错误码。

## 影响

- 改动集中在 `apps/web/src/app/`（AuthGate、providers、AppLayout）与 `LoginPage.tsx`、`api/hooks.ts`。
- 不改后端任何认证逻辑。
