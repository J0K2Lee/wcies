# 扫码载体选型结论：Code128 一维条码（本轮只出结论，不实现）

- **状态**：已决策（2026-09-11，Sprint 6 任务书决策 #18）
- **范围**：仓库作业场景（收货、拣货、盘点、拦截回库、库位标签、SKU 标签）

## 结论

WCIES 仓库场景的扫码载体采用 **Code128 一维条码**。

## 理由

1. **设备适配**：仓库场景的标配是激光扫码枪。一维码在激光扫码枪下识别速度最快、抗倾斜/污损能力最好、设备最便宜；二维码主要依赖影像式扫码器（成本更高，且对手持角度更敏感）。
2. **数据形态**：当前需要扫出的只有一个字段——编码（内部条码 `WCSKU%08d`、库位条码 `BIN-{仓库}-{库位}`、将来的单据条码）。一维码完全承载，不需要"一次扫出多个字段"。
3. **不用 EAN-13**：EAN-13 需要申请 GS1 前缀，且位数/校验规则固定，不适合作为内部编码载体。Code128 无长度限制、支持全 ASCII，是内部编码的行业标准选择。
4. **何时才需要二维码**：只有当标签需要同时携带多个字段（SKU + 批次 + 数量 + 序列号打包在一个标签里）或标签面积受限需要高密度编码时，才值得切换二维码。届时系统内部条码值不变，仅更换标签的印刷格式，迁移成本可控。

## 对现有编码的影响

无。内部条码 `WCSKU%08d` 与库位条码 `BIN-*` 的**值**不变；Code128 只是这些值的印刷/识别格式。打印模板（SKU 标签、库位标签）在后续 Sprint 实现时选用 Code128-B 子集即可（支持全 ASCII）。
