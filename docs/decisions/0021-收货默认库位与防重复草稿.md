# ADR 0021 — 收货单默认库位（SKU 现存货位 → 暂存位）；从采购单生成收货单防重复

日期：2026-10-15（用户拍板，采购/收货流程优化）
状态：已接受（细化 0013 §8 的暂存方案 A；不推翻 DEFAULT 规则）

## 背景

Sprint 7 引入采购单 / 收货单分离（决策 0013）后，实际收货作业暴露两个问题：

1. **默认库位缺失，收货被反复打断**。从采购单生成的收货草稿，明细 `bin_id`
   恒为 `null`；确认收货时 `resolveDimension` 对“已有库位的仓库”强制要求显式
   `binId`（0013 §8 方案 A），于是点「确认收货」被拦下、强制打开编辑器逐行选
   库位、保存草稿、再确认——同一次收货点了两次确认按钮。而绝大多数来货就是
   补同一 SKU，理应默认回到该 SKU 现存的库位。
2. **生成收货单没有防重**。`generateFromPo` 不检查该采购单是否已有未取消的收货
   单，对同一 PO 连续生成会得到两张按同一“未收数量”预填的草稿；先后确认会把
   `purchase_order_items.received_quantity` 累加超量，撞上 DB CHECK
   `ck_purchase_order_items_received` 后经全局过滤器回落成 `COMMON_DATABASE_ERROR`
   **500**，操作者看到“数据库错误”而非可读原因。

## 决策

### 1. 收货草稿默认库位：逐 SKU 解析，预填可改

生成收货草稿（`generateFromPo`、批量生成、采购单创建时同步生成草稿）时，为**每
一行**解析默认库位，写入草稿明细的 `bin_id`：

1. **SKU 现存货位优先**：取该 SKU 在本仓 `SELLABLE`、`on_hand > 0` 的库位中
   `on_hand` 最大者；并列时按 `bin_code` 升序取第一个（结果确定可复现）。
2. **无现货则暂存位**：该 SKU 在本仓无正数 `SELLABLE` 在库时，用本仓 `ST` 区
   第一个库位（`bin_code` 升序）。**不存在 `ST` 区库位时自动创建一个**
   （`zone='ST', rackNumber=1, level='1'`，即收货页「创建暂存库位（ST 区）」同款），
   本批全部无货 SKU 共用同一个；写入库位操作日志。
3. **仓库完全没有库位**时 `bin_id` 保持 `null`：走库存层既有的虚拟 `DEFAULT`
   库位（0013 §8 不放宽），此时自动建 `ST` 位只会制造噪音。
4. **显式传入的 `defaultBinId` 覆盖全部行**（保留原 API 契约，集成测试与导入
   脚本继续可用）。
5. 默认值**只是预填**，操作者可逐行改（含改到另一个库位）。库位可能放满，
   需要新库位时照旧在草稿里选/建——这正是保留可改的原因。

该默认值同时服务两条生成路径，保证口径一致：
`PurchaseReceiptService.resolveDefaultReceiptBins()` 为唯一实现，PO 创建时的草稿
也在事务外调用它；`ST` 位自动创建会写库位与操作日志，故不得挂进采购单事务。

### 2. 从采购单生成收货单：防重复草稿

`generateFromPo` 在解析仓库/明细之前，检查该 PO 是否已有**未取消**（`DRAFT` 或
`RECEIVED`）的收货单：

- 已有任意 **`DRAFT`** → 拒绝，返回
  `PURCHASE_RECEIPT_DUPLICATE_DRAFT`（409，消息含已有 `PR` 号），引导操作者去
  编辑确认那张草稿。批量生成逐单复用同一逻辑，天然得到逐单失败结果（AGENTS §36）。
- 已有 **`RECEIVED`**、无 `DRAFT` → 允许（分批到货：先确认一批，再生成下一批）。
- 显式取消的草稿不计入，取消后可重新生成。

### 3. 确认收货：超收前置校验（兜底）

确认收货在**事务内、行锁之后**逐行校验：本次数量 ≤ 来源采购明细的未收数量
（`quantity - received_quantity`）。超出时抛 `PURCHASE_RECEIPT_EXCEEDS_ORDERED`
（409，含 SKU / 采购量 / 已收 / 本次），整单回滚、不写库存。

这是防御而非主路径：正常流程由 §2 防重挡住；该校验兜住历史遗留草稿、并发草稿
或人工放大数量，避免撞 DB CHECK 后回落成不可读的 500。

## 影响

- `warehouse` 模块新增 `WarehouseBinService.ensureReceiptStagingBin()`（幂等，
  返回 `ST` 区第一个库位或新建）、`WarehouseRepository.findFirstBinByZone()`。
- `inventory` 模块新增 `InventoryQueryService.findCurrentBinId(skuId, warehouseId)`。
- `purchase` 模块新增 `PurchaseReceiptService.resolveDefaultReceiptBins()`（public，
  供 PO 创建路径复用）；`generateFromPo` 加防重；`confirm` 加超收校验。
- `PurchaseOrderService.create()` 注入 `PurchaseReceiptService`（同模块内，无环）。
- 新增错误码：`PURCHASE_RECEIPT_DUPLICATE_DRAFT`、`PURCHASE_RECEIPT_EXCEEDS_ORDERED`
  （purchase.md §8）。
- 无 Schema 变更（无新列、无新约束），无需 Migration。
- `docs/business-rules/purchase.md` §3.3 / §4.2 / §4.3 / §8 同步更新。

## 明确不改

- 不放宽 0013 §8 的“已有库位仓库必须显式 binId”约束本身——本决策只是把**默认
  值**在生成草稿时就填好，`resolveDimension` 与确认路径的硬约束不变。
- 不改采购单状态机、确认收货的事务/幂等/移动加权成本规则（0013 §5/§6 不变）。
