规则 ① Resolver 订单安全边界

解析必须带 storeId（结构性保证）
Repository 层查询永远携带 WHERE store_id = ?，全局 offer_id 查找在代码路径上不可能发生。
resolveInternalSku({ storeId, offerId?... })
  标识全空          → LISTING_SKU_RESOLVE_FAILED
  同店 0 候选       → LISTING_SKU_RESOLVE_FAILED
  同店 >1 候选      → LISTING_SKU_RESOLVE_AMBIGUOUS
                      // 绝不"取第一条"
  唯一命中          → 返回 Internal SKU
实测：OZON-A 与 OZON-B 同 offerId="ABC" 各解析到正确 SKU； 跨店同字符串不冲突、同店重复即拒绝。

规则 ② 条码唯一 + 单主条码

一个条码永远只绑一个 SKU
uq_sku_barcodes_barcode 全局唯一，冲突报 SKU_BARCODE_ALREADY_EXISTS。
每 SKU 最多一个 is_primary = true
数据库 Partial Unique Index 兜底（WHERE is_primary），切换主条码在事务内先降级旧主条码，不只靠前端。
类型说明
EAN / GTIN69 码归入此语义，不建 CN_69_CODE
MANUFACTURER厂商条码
INTERNAL系统生成 WCSKU%08d

规则 ③ 店仓绑定双校验（Service 层）

创建 Binding(store, warehouse, mode)
  ① 平台一致    mode 前缀平台 == store 平台
     WB 店铺 + OZON_FBO → 拒绝
  ② 仓库类型匹配
     FBO/FBY/FBW  → 仅 PLATFORM 仓
     FBS/RFBS/FBP → SELF / THIRD_PARTY 仓
     OZON_FBO + SELF 仓 → 拒绝
  ③ 三元组去重  store+warehouse+mode 已存在 → 拒绝
履约语义只存在于 Binding / 常量层，不污染 Inventory Core； 一个仓库可被多店共享（深圳仓实测绑 3 店），warehouse.store_id 被禁止。
